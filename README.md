# obsidian-schemas

Canonical Pydantic entity schemas for Obsidian frontmatter, used by HAL9000 and Exocortex projects.

## Overview

This package provides:

- **Pydantic models** for Obsidian entity types (Person, Company, Book, etc.)
- **Parser module** for reading markdown frontmatter into typed models
- **Writer module** for writing models back to markdown files
- **Repository layer** for loading, querying, and managing entities
- **Full round-trip support** - preserves fields not in the model

## Installation

```bash
# From source (development)
pip install -e /path/to/obsidian-schemas

# Or add to pyproject.toml dependencies
# obsidian-schemas = { path = "../obsidian-schemas" }
```

## Entity Types

The following entity types are supported, matching the templates in the Obsidian vault:

### Person
Contacts and people (`@Name.md` files)

```python
from obsidian_schemas import Person

person = Person(
    name="John Smith",
    emails=["john@example.com"],
    phones=["447990558521"],
    company="Acme Corp",
    title="CTO",
    linkedin="https://linkedin.com/in/johnsmith",
    roles=["vip", "coaching-client"],
    tags=["person"],
    created="2025-01-01",
)

# Role helpers
person.has_role("vip")  # True
person.has_any_role("vip", "family")  # True
```

Fields: `type`, `name`, `aliases`, `emails`, `phones`, `whatsapp`, `company`, `title`, `linkedin`, `roles`, `tags`, `created`

**Roles**: Array of role identifiers that modify assistant behavior. Defined roles: `vip`, `coaching-client`, `family`, `investor`, `active`. See `rules.md` for full role definitions and combination rules.

### Company
Organizations (`@CompanyName.md` files)

```python
from obsidian_schemas import Company

company = Company(
    name="Acme Corp",
    website="https://acme.com",
    industry="Technology",
    linkedin="https://linkedin.com/company/acme",
    tags=["company"],
    created="2025-01-01",
)
```

Fields: `type`, `name`, `website`, `industry`, `linkedin`, `tags`, `created`

### Book
Reading list items (`Title - Author.md` files)

```python
from obsidian_schemas import Book

book = Book(
    title="Children of Time",
    author="Adrian Tchaikovsky",
    status="read",  # to-read, reading, read, abandoned
    rating="5",
    isbn="9781447273301",
    tags=["book", "Fiction"],
)
```

Fields: `type`, `title`, `author`, `description`, `status`, `rating`, `isbn`, `publisher`, `publication_year`, `source_url`, `date_added`, `date_finished`, `tags`

### Watch
Films/series to watch

Fields: `type`, `title`, `media_type`, `director`, `year`, `status`, `rating`, `streaming_service`, `recommended_by`, `date_added`, `date_watched`, `tags`

### Explore
Links/topics to explore

Fields: `type`, `subtype`, `title`, `url`, `source`, `status`, `created`, `tags`

### GiftIdea
Gift ideas for people

Fields: `type`, `for`, `source`, `date_added`, `tags`

### Meeting
Meeting notes (generated by Exocortex)

Fields: `type`, `date`, `attendees`, `topics`, `meeting_id`, `tags`

## Usage

### Parsing Markdown Files

```python
from obsidian_schemas import parse_markdown_file, Person

# Parse a file - automatically detects entity type
doc = parse_markdown_file("/path/to/@John Smith.md")

# Access typed entity
if isinstance(doc.entity, Person):
    print(f"Name: {doc.entity.name}")
    print(f"Email: {doc.entity.get_primary_email()}")
    print(f"Company: {doc.entity.company}")

# Access body content
print(doc.body)

# Access extra fields not in the model
print(doc.extra_fields)
```

### Parsing Content Strings

```python
from obsidian_schemas import parse_frontmatter
from obsidian_schemas.parser import parse_markdown_content

content = """---
type: person
name: John Smith
emails:
  - john@example.com
custom_field: preserved
---

# John Smith

Some notes here.
"""

# Parse to document
doc = parse_markdown_content(content)
print(doc.entity.name)  # "John Smith"
print(doc.extra_fields)  # {"custom_field": "preserved"}
```

### Writing Markdown Files

```python
from obsidian_schemas import Person, write_markdown_file

# Create entity
person = Person(
    name="Jane Doe",
    emails=["jane@example.com"],
    company="Tech Corp",
    tags=["person"],
    created="2025-01-01",
)

# Write to file
write_markdown_file(
    "/path/to/@Jane Doe.md",
    entity=person,
    body="# Jane Doe\n\n## Timeline\n",
)
```

### Updating Fields

```python
from obsidian_schemas.writer import update_frontmatter_field, update_frontmatter_fields

# Update single field
update_frontmatter_field("/path/to/@John.md", "company", "New Company")

# Update multiple fields
update_frontmatter_fields("/path/to/@John.md", {
    "company": "New Company",
    "title": "CEO",
})
```

## Repositories

Repositories provide high-level access to entities with indexing and queries.

### PersonRepository

```python
from obsidian_schemas import PersonRepository

# Initialize with vault path (or uses OBSIDIAN_VAULT_PATH env var)
repo = PersonRepository("/path/to/vault")

# Get by name (case-insensitive)
person = repo.get("John Smith")

# Get by email
person = repo.get_by_email("john@example.com")

# Get by phone (handles various formats)
person = repo.get_by_phone("+447990558521")
person = repo.get_by_phone("447990558521@s.whatsapp.net")

# Get by alias
person = repo.get_by_alias("Johnny")

# Smart resolve - tries name, alias, email, phone, partial match
person = repo.resolve("john@example.com")

# Query by role or company
vips = repo.get_by_role("vip")
acme_people = repo.get_by_company("Acme Corp")

# Create a stub contact
person = repo.create_stub("New Contact", email="new@example.com")

# Refresh cache after vault changes
repo.refresh()
```

### CompanyRepository

```python
from obsidian_schemas import CompanyRepository

repo = CompanyRepository("/path/to/vault")

# Get by name
company = repo.get("Acme Corp")

# Get by domain
company = repo.get_by_domain("acme.com")
company = repo.get_by_domain("https://www.acme.com/about")

# Query by industry
tech_companies = repo.get_by_industry("Technology")

# Create a stub company
company = repo.create_stub("New Startup", website="https://newstartup.com")
```

### Round-Trip Preservation

The parser and writer preserve fields that aren't in the model:

```python
from obsidian_schemas import parse_markdown_file, write_markdown_file

# Parse existing file (may have custom fields)
doc = parse_markdown_file("/path/to/@John.md")

# Modify the entity
doc.entity.company = "Updated Company"

# Write back - extra fields preserved
write_markdown_file(
    "/path/to/@John.md",
    entity=doc.entity,
    body=doc.body,
    extra_fields=doc.extra_fields,
    overwrite=True,
)
```

## Forward Compatibility

All models use `extra = "allow"` in their Pydantic config, which means:

1. Files with extra frontmatter fields can be parsed without errors
2. Extra fields are accessible via `entity.model_extra`
3. The `ParsedDocument.extra_fields` dict captures fields not in the model
4. Round-trip operations preserve these extra fields

This allows the schemas to evolve without breaking existing files.

]
